== General information

=== What Baryonyx does

Baryonyx reads a problem in the CPLEX LP format and searches for 0-1
solutions:

* in *solve mode* (default), it searches for a solution that satisfies every
  constraint;
* in *optimization mode* (`-O`), it also improves the objective until the
  time limit is reached or the search is interrupted.

Baryonyx is a heuristic: it finds good solutions quickly on large problems,
often much larger than an exact solver can handle in the same time, but it
never proves optimality. Use an exact solver (CPLEX, Gurobi, HiGHS, SCIP) when
a proof is required.

Supported problems:

* 0-1 variables (real variables are solved as 0-1 variables with a warning,
  general integer variables are rejected);
* equality, less and greater constraints with integer coefficients;
* linear or quadratic objective functions, minimized or maximized;
* problems without constraint.

=== Quick start

Search for a feasible solution:

[source,bash]
....
baryonyx-0.5 file.lp
....

Optimize for 60 seconds with 8 threads:

[source,bash]
....
baryonyx-0.5 -O -p time-limit=60 -p thread=8 file.lp
....

Baryonyx writes the best solution in `file.lp-<pid>.sol`, one `name=value`
line per variable after a commented header. When no solution is found, the
file contains the reason (`\ Solution not found. Error: ...`).

`Ctrl-C` (or `SIGTERM`) stops the search: Baryonyx writes the best solution
found so far and exits. Without time limit, the optimization runs until it is
stopped this way.

Check that a solution file satisfies the constraints of a problem and compute
its value:

[source,bash]
....
baryonyx-0.5 --check file.sol file.lp
....

== Technical overview

=== From the LP file to the solution

. *Parsing* (`lib/src/parser.cpp`): reads the CPLEX LP file into a
  `raw_problem` (objective, constraints, bounds and variable types). The
  parser accepts constraints without terms, written by CPLEX, and drops zero
  coefficients.
. *Preprocessing* (`lib/src/preprocessor.cpp`): fixes the variables forced by
  the constraints, removes the satisfied constraints and propagates. The
  `--disable-preprocessing` option skips this step and `--debug` writes the
  reduced problem in `preprocessed.lp`.
. *Selection of the solver class* (`lib/src/problem.hpp`) according to the
  constraint types and coefficients, see below.
. *Solve or optimization* (`lib/src/itm.hpp`): the solver searches for a
  feasible solution, the optimizer drives the solver to improve it.
. *Result*: the solution is mapped back to the original variables and written
  in the `.sol` file.

=== The In The Middle heuristic

Each constraint `k` has a Lagrangian multiplier `π_k` and each non-zero
coefficient `a_kj` a preference `P_kj`. For each violated constraint, the
solver computes the reduced costs `r_j = c_j − Σ_i a_ij π_i − Σ_i a_ij P_ij`
of its variables, sorts them and sets the
variables so that the constraint becomes satisfied, choosing `π_k` "in the
middle" of the two reduced costs at the boundary. The preferences are pushed
away from the boundary by a factor `κ`, which grows during the search
(`kappa-min`, `kappa-step`, `alpha`) until the solution stabilizes or κ
exceeds `kappa_max`. `θ` (`theta`) keeps a part of the preferences between
two loops and `δ` (`delta`) is a small random perturbation that breaks ties.

Once a feasible solution is found, the *pushes* amplify the objective in the
reduced costs to improve the solution while keeping it feasible.

`kappa_max` and the pushes settings are fixed, as `static inline constexpr`
members of `solver_parameters` (`lib/include/baryonyx/core`), because they
have little influence on the results:

[cols="2,1,5a", options="header"]
|===
| constant | value | role

| `kappa_max`
| 0.6
| The solver stops when κ exceeds this value.

| `pushes_limit`
| 100
| Number of pushes after a feasible solution is found.

| `pushing_iteration_limit`
| 50
| Number of loops after a push before trying the next one.

| `pushing_k_factor`
| 0.9
| Factor applied to κ during a push.

| `pushing_objective_amplifier`
| 5
| Factor applied to the costs during a push.
|===

The costs are normalized before the search (`norm`, default: divided by their
largest absolute value).

=== Solver classes

The solver class is chosen from the constraint types and the coefficients
of the preprocessed problem. All solvers share the same In The Middle loop
(`lib/src/itm-solver-common.hpp`) and only differ in the way they satisfy a
constraint.

[cols="2,2,5a", options="header"]
|===
| class | problems | implementation

| `equalities_01`
| equality constraints only, coefficients in `{1}`
| `lib/src/itm-solver-equalities-01.cpp`. Sorts the reduced costs of the
  constraint and selects the `b` best variables.

| `equalities_101`
| equality constraints only, coefficients in `{-1, 1}`
| `lib/src/itm-solver-equalities-101.cpp`. Same as above, the negative
  coefficients are handled by a change of variable `y = 1 − x`.

| `inequalities_01`
| any constraint type, coefficients in `{1}`
| `lib/src/itm-solver-inequalities-01.cpp`. Selects a number of variables in
  the `[min, max]` interval of the constraint.

| `inequalities_101`
| any constraint type, coefficients in `{-1, 1}`
| `lib/src/itm-solver-inequalities-101.cpp`. Same as above with the change of
  variable for negative coefficients.

| `inequalities_Z` (also used for `equalities_Z`)
| at least one coefficient outside `{-1, 0, 1}`
| `lib/src/itm-solver-inequalities-Z.cpp`. Each constraint uses its own
  sub-solver:

* *linear* when its coefficients are in `{-1, 1}`;
* *exhaustive* (`lib/src/exhaustive-solver.hpp`) for short constraints
  (fewer than 10 variables) with larger coefficients: all the valid
  assignments are enumerated once, then the best one is selected at each
  loop;
* *branch and bound* (`lib/src/branch-and-bound-solver.hpp`) for the other
  constraints.

| `inequalities_101` buffered
| classes `01` and `101`, with `-p buffer-solver=1`
| `lib/src/itm-solver-inequalities-101-buffered.cpp`. Experimental. The
  constraints are colored once so that the constraints of the same color
  share no variable; each color is computed in parallel on `thread` threads
  and the preferences are updated afterwards. The results differ from the
  sequential solvers. It is only faster on very large problems (millions of
  variables) with 4 threads or more.
|===

Each class is instantiated for two cost types:

* `default_cost_type`: linear objective;
* `quadratic_cost_type`: quadratic objective (`[ ... ] / 2` terms in the LP
  file); the reduced costs include the quadratic terms of the current
  solution.

A problem without constraint does not run the heuristic: the solution comes
directly from the sign of the costs (linear objective) or from a tabu search
(quadratic objective).

=== Optimizers

In optimization mode (`-O`), the `optimizer` parameter selects the algorithm
that drives the solver:

[cols="1,6a", options="header"]
|===
| optimizer | algorithm

| `lns` (default)
| Large neighbourhood search (`lib/src/lns-optimizer.cpp`). A first solution
  comes from `restart`, then `tuned` if needed. Then, in a loop, most
  variables are fixed to their value in the best solution and a small
  neighbourhood is freed, alternating constraint-linked variables and random
  variables; the reduced problem is preprocessed and solved by a short
  `restart` run. The neighbourhood size adapts to the success of the
  previous runs.

| `restart`
| Independent restarts of the solver from the best solution, adapting the
  kappa step (`lib/src/itm-restart-optimizer.hpp`).

| `genetic`
| A population of solutions with crossovers and mutations
  (`lib/src/itm-optimizer-common.hpp`). Its settings (population size,
  crossover and mutation laws) are fixed in `solver_parameters` because they
  have little influence on the results.

| `tuned`
| Successive halving (`lib/src/tuned-optimizer.cpp`): random settings of the
  optimizer (`genetic`, `restart`, `lns`) and of the solver parameters
  (`theta` up to 0.95, `delta`, `kappa-min`, `kappa-step`,
  `init-policy-random`, `constraint-order`) compete on half of the time
  limit, then the best setting runs for the remaining half. Useful when the
  default parameters do not find a solution.
|===

The `--auto:branch` mode (`lib/src/branch-optimizer.cpp`) splits the problem
on a variable chosen in the most violated constraints, solves both
sub-problems (variable fixed to 0 or 1) with the selected optimizer and keeps
the best solution.

=== Parallelism

* In optimization mode, the `thread` parameter sets the number of solvers
  running in parallel; they share the best solution.
* In solve mode, `thread` only matters for the buffered solver
  (`buffer-solver=1`).
* The `seed` parameter makes a run reproducible for a given number of
  threads.

==== In The Middle parameters

[cols="2,1,1,5a", options="header"]
|===
| name | type | default | summary

| `theta`
| real [0, 1]
| 0.5
| Part of the preferences kept between two loops. High values (0.7 to 0.9)
  help on set partitioning problems where the search oscillates.

| `delta`
| real ]0, +∞[
| automatic
| Random perturbation of the preferences that breaks ties. Computed from
  the costs and `theta` when not set.

| `kappa-min`
| real [0, 1]
| 0
| Initial value of κ.

| `kappa-step`
| real [0, 1]
| 0.001
| Growth of κ at each loop.

| `alpha`
| real [0, 2]
| 1
| Adaptiveness of κ: the step is multiplied by
  `(remaining constraints / constraints)^alpha`.

| `w`
| real [0, +∞[
| 0.05
| Warm-up: number of loops without updating κ. Below 1, it is a
  fraction of `limit`.

| `norm`
| string
| `loo`
| Cost normalization:

* `loo`: divide by the largest absolute value;
* `l1`: divide by the sum of absolute values;
* `l2`: divide by the euclidean norm;
* `random`: add a small noise to break equal costs, then `loo`;
* `none`: unmodified costs.

| `constraint-order`
| string
| `none`
| Order of the violated constraints at each loop:

* `none`: the order of the LP file;
* `reversing`: the reverse order;
* `random-sorting`: a random order;
* `infeasibility-decr`, `infeasibility-incr`: sorted by violation, in
  decreasing or increasing order;
* `lagrangian-decr`, `lagrangian-incr`: sorted by Lagrangian multiplier, in
  decreasing or increasing order;
* `pi-sign-change`: a random order when the signs of the multipliers change;
* `cycle`: switch between the previous orders.

| `preprocessing`
| string
| `none`
| Order of the constraint matrix:

* `none`: the order of the LP file for constraints and variables;
* `memory`: the order of the LP file for constraints, variables sorted to
  improve the memory cache efficiency;
* `less-greater-equal`, `less-equal-greater`, `greater-less-equal`,
  `greater-equal-less`, `equal-less-greater`, `equal-greater-less`:
  constraints sorted by type in this order, variables sorted as in `memory`;
* `p1`, `p2`, `p3`, `p4`: reserved.

| `buffer-solver`
| 0 or 1
| 0
| Use the experimental buffered solver for the `01` and `101` classes, with
  parallel computation of the constraints in solve mode.
|===

==== Initialization parameters

[cols="2,1,1,5a", options="header"]
|===
| name | type | default | summary

| `init-policy`
| string
| `bastert`
| Initialization of the solution vector:

* `bastert`: set each variable from the sign of its cost;
* `pessimistic-solve`: satisfy each constraint with the fewest variables set
  to one;
* `optimistic-solve`: satisfy each constraint with the most variables set to
  one.

| `init-policy-random`
| real [0, 1]
| 0.5
| Probability to use `init-policy` for a variable; otherwise its value is
  drawn at random.
|===

==== Optimizer parameters

[cols="2,1,1,5a", options="header"]
|===
| name | type | default | summary

| `optimizer`
| string
| `lns`
| Optimization algorithm: `lns`, `restart`, `genetic` or `tuned`, see

| `optimizer-warm-start`
| 0 or 1
| 0
| Keep π and P between two solver runs instead of resetting them. Slower in

== Benchmark

Baryonyx runs benchmarks on a set of problems described in `csv` files with
the `--bench [name]` option. All Baryonyx parameters are available to perform
the benchmark.

For example:

[source,bash]
....
baryonyx-0.5 --bench bx-0.5 -p delta=0.01 -p time-limit=60 spp.csv
....

The benchmark mode updates the `csv` file with the results of the
computation. The `csv` format is:

....
file optimum status cplex lsp bx-0.2 <1>
cplex:
lsp:    <2>
bx-0.2:
scp410 optimum 514 514 514 804 <3>
scp41 optimum 429 429 429 627
scp42 optimum 512 512 512 934
....

<1> The header: three mandatory columns (`file`, `optimum`, `status`) and one
column per solver. In this example, cplex, local solver and baryonyx 0.2.
<2> The description part: one line per solver to describe its version and
parameters for example.
<3> Finally, one line per problem: model name (with or without extension),
status (optimum/feasible), best solution known and the solution of each
solver. `inf` indicates that no solution was found.

The `benchmarks` directory provides some files and a script to download
classical problems.

=== API

Two functions are provided to solve or optimize 01 linear programming
problem. Parameters are the same as `C++ API`. These function returns a
scalar:

* If a solution is found:
** if the problem is a minimization: the value of the solution found.
** if the problem is a maximization: the inverse of the solution found.
* If no solution is found, we use the limits of the objective function (minimal
  and maximal value possible.
** if the problem is a minimization: the maximal value possible + the remaining
   constraints.
** if the problem is a maximization: the inverse of the minimal value possible
   + the remaining constraints.
* If a error occurred (not enough memory, problem error etc.):
** if the problem is a minimization: the maximal value possible + the number of
   constraints .
** if the problem is a maximization: the inverse of the minimal value possible
   + the number of constraints.

[source,R]
----
solve_01lp_problem <- function(file_path, limit = 1000L, theta = 0.5,
  delta = -1, pre_constraint_order = 1L, constraint_order = 0L,
  kappa_min = 0.0, kappa_step = 1e-3, alpha = 1.0, w = 0.05,
  time_limit = 10.0, seed = -1L, thread = 1L, norm = 4L, init_policy = 0L,
  init_policy_random = 0.5, verbose = TRUE)

optimize_01lp_problem <- function(file_path, limit = 1000L, theta = 0.5,
  delta = -1, pre_constraint_order = 1L, constraint_order = 0L,
  kappa_min = 0.0, kappa_step = 1e-3, alpha = 1.0, w = 0.05,
  time_limit = 10.0, seed = -1L, thread = 1L, norm = 4L, verbose = TRUE)
----

=== Usage

Apply morris method to found useful parameters:

[source,R]
----
library(rbaryonyx)
library(sensitivity)

factors = c("theta", "delta", "constraint_order", "kappa_min", "kappa_step",
  "alpha", "w", "norm")

bounds = data.frame(
  min=c(
    0,     # theta
    0,     # delta
    0,     # constraint_order
    0,     # kappa_min
    1e-16, # kappa_step
    0.0,   # alpha
    50,    # w
    0,     # norm
    0,     # init_policy
    0.0,   # init_random
    0
    ),    # float_type
max=c(
    1,     # theta
    0,     # delta
    4,     # constraint_order
    0.1,   # kappa_min
    1e-1,  # kappa_step
    2.0,   # alpha
    500,   # w
    4,     # norm
    2,     # init_policy
    1.0,   # init_random
    2))    # float_type

rownames(bounds) <- factors

morrisDesign <- morris(model = NULL,
                factors = factors,
                r = 10,
                design=list(type="oat", levels=10, grid.jump=5),
                binf = bounds$min,
                bsup = bounds$max,
                scale=TRUE)

solve_lp <- function(x, file_path, limit=10000, time_limit=10, seed=123456789, thread=1) {
  r <- rbaryonyx::solve_01lp_problem(file_path = file_path,
                   limit = limit,
                   theta = x["theta"],
                   delta = x["delta"],
                   constraint_order = x["constraint_order"],
                   kappa_min = x["kappa_min"],
                   kappa_step = x["kappa_step"],
                   alpha = x["alpha"],
                   w = x["w"],
                   time_limit = time_limit,
                   seed = seed,
                   thread = thread,
                   norm = x["norm"],
                   init_policy = x["init_policy"],
                   init_random = x["init_random"],
                   float_type = x["float_type"])

  return(r)
}

r = apply(morrisDesign$X, 1, solve_lp, file_path="verger_5_5.lp", thread=1, limit=10000, time_limit=10, seed=123456789)

morrisDesign$Y <- r
mu <- apply(morrisDesign$X,2,mean)
mu.star <- apply(morrisDesign$X, 2, function(x) mean(abs(x)))
sigma <- apply(morrisDesign$ee, 2, sd)

apply(morrisDesign$X, 2, function(v) plot(factor(v), r))
----
